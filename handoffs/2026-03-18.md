Mercury remains code-only, with the pointer note at:

### Current Batch view

Current Batch now behaves as the main review surface:
- one canonical row per Batch 0 question, using the latest real rerun
- rerun history remains inside each row behind `show rerun history`
- `Question History` section was removed as redundant
- lightweight type group rows were restored, without reintroducing a repeated type column

### Filtering / navigation

Dashboard controls were simplified:
- removed the old top-level filter block
- removed the type filter bar
- moved result filtering (`all results`, `ok only`, `miss only`) into `Current Batch`
- `Reason Overview` is now the reason filter surface
- removed the extra `all reasons` filter row
- added a single `clear reason filter` button

### Current Batch table layout

The Current Batch table was rebalanced to keep attention on the useful columns:
- narrow columns stay narrow: question id, latest run, profile, result, files
- wider columns: reason and prompt
- history got more space so pills stop pushing past the border
- question-history archive section was removed
- fixed-layout and wrapping stay in place to prevent the table exceeding the panel width

### Current Batch analysis labels

The heuristic labeling was tightened:
- answer-side failure labels now only apply when benchmark answer-session coverage is full
- partial answer-session coverage falls back to retrieval-side buckets

Important examples:
- `5a7937c8` moved from answer-side blame to retrieval-side blame because only part of the answer-session set was covered
- `852ce960` moved to retrieval-side blame for the same reason
- `505af2f5` and `fca70973` remain answer-side because their answer-session coverage is full

### Time-related miss labels

The time miss logic was revised to match the real issue you care about:
- only misses with explicit `time_frame` set get the special label `explicit-time-window-miss`
- if `time_retrieval_mode = all` but `time_frame` is empty, the case falls back to a normal retrieval miss bucket

This means:
- `bc149d6b` and `75832dbd` are true explicit-window misses
- `2a1811e2` is no longer treated as a time-window miss

### Retrieval coverage surfacing

Current Batch rows now show coverage flags even when the answer is correct:
- partial coverage is flagged, for example `partial coverage 1/2`
- no answer-session coverage is also flagged

This is useful for “correct but still not robust” cases like abstentions that happened to be right.

## Question Detail Page Changes

### Retrieved memory cards

Question pages now show readable memory cards instead of raw JSON blobs.

Memory cards were simplified for scanability:
- removed `location`, `category`, `object`, and `emotion`
- kept `identifier`, `summary key`, `time`, `description`, `details`, and `keys`

### Session-level retrieval understanding

Question pages make session coverage clearer:
- benchmark answer sessions are shown first in the session section
- retrieved memories are compared against benchmark `answer_session_ids`
- `Retrieval Quality` shows:
  - answer sessions total
  - answer sessions retrieved
  - retrieved answer session ids
  - missing answer session ids

### Retrieved Memories layout

The retrieved-memory section was redesigned:
- removed separate “From Answer Sessions” and “Other Retrieved Memories” subsections
- replaced them with a single fixed-width card grid
- cards are ordered by haystack session so same-session memories stay adjacent
- each session gets a pill in the card header
- the same session uses the same pill color on the page
- different sessions now use clearly different colors from a per-page palette

### Session collapse behavior

Question-session conversation blocks are now collapsed by default, including prioritized sessions, so detail pages do not open with too much content expanded.
